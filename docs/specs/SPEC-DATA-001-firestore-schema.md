# SPEC-DATA-001: Firestore Schema

**Created:** 2026-01-18
**Status:** Active
**Author:** Claude Code Audit

## 1. Overview

This document defines the complete Firestore data model for the Abundance inventory cataloging application. The schema supports:

- **Real-time sync** via Firestore listeners (iOS client)
- **Offline-first** with local persistence enabled
- **Row-level security** with user data isolation
- **AI pipeline integration** with status-driven triggers
- **Two-phase capture** with sessions for object detection and items for cataloging

### Design Principles

1. **Root Collections**: All collections (`users`, `items`, `sessions`) are at root level for maximum query flexibility
2. **Denormalization**: `userId` is stored in each document for ownership verification and queries
3. **Status-Driven Triggers**: Cloud Functions trigger on document status changes (e.g., `status: 'pending'` triggers AI processing)
4. **Flattened Schema**: AI results are flattened to top-level fields for simpler client queries
5. **Soft Deletes**: Items use `deletedAt` timestamp for recovery capability

### Database Configuration

| Setting | Value |
|---------|-------|
| Mode | Native mode (not Datastore mode) |
| Region | us-central1 |
| Offline Persistence | Enabled on iOS SDK |
| Security | Firestore Security Rules |

### 2.1 `users` Collection

User profiles and subscription status.

**Document ID:** Firebase Auth UID (e.g., `firebase_user_abc123`)

#### Schema

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `userId` | string | Yes | Firebase Auth UID (redundant for queries) |

| `displayName` | string | No | Display name from Apple Sign-In |

| `updatedAt` | timestamp | Yes | Last profile update |

### 2.2 `sessions` Collection

Capture sessions for multi-image object detection (Layer 1).

**Document ID:** Auto-generated by Firestore

#### Schema

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | string | Yes | Session document ID |
| `userId` | string | Yes | Owner's Firebase Auth UID |
| `captureMode` | string | Yes | `"single"`, `"burst"`, or `"sweep"` |
| `status` | string | Yes | Session processing status |
| `originalImageUrls` | array | Yes | GCS URLs to original images |
| `imagesUploaded` | number | No | Count of uploaded images |
| `expectedImageCount` | number | No | Expected total images for burst |
| `detectedObjects` | array | No | Array of detected objects |
| `reasoning` | string | No | AI reasoning for detection results |
| `error` | string | No | Error message if failed |
| `errorCode` | string | No | Error code for categorization |
| `sweepCrops` | array | No | Pre-cropped segments from on-device EdgeTAM (sweep mode only) |
| `failedAt` | timestamp | No | Failure timestamp |
| `processingStartedAt` | timestamp | No | Processing claim timestamp (idempotency) |
| `createdAt` | timestamp | Yes | Session creation timestamp |
| `detectedAt` | timestamp | No | Detection completion timestamp |

#### Status Values

| Status | Description |
|--------|-------------|
| `uploading` | Images being uploaded to GCS |
| `detecting` | AI detection in progress |
| `detected` | Detection complete, objects found |
| `failed` | Detection failed with error |

#### TypeScript Interface

```typescript
type SessionStatus = 'uploading' | 'detecting' | 'detected' | 'failed';
type CaptureMode = 'single' | 'burst' | 'sweep';

interface CaptureSession {
  id: string;
  userId: string;
  captureMode: CaptureMode;
  status: SessionStatus;
  createdAt: FirebaseFirestore.Timestamp;
  detectedAt?: FirebaseFirestore.Timestamp;
  originalImageUrls: string[];
  imagesUploaded?: number;
  expectedImageCount?: number;
  detectedObjects?: DetectedObject[];
  reasoning?: string;
  error?: string;
  errorCode?: string;
  /** Sweep mode: pre-cropped segments from on-device EdgeTAM */
  sweepCrops?: SweepCropInfo[];
  failedAt?: FirebaseFirestore.Timestamp;
  processingStartedAt?: FirebaseFirestore.Timestamp;
}

/** Sweep crop metadata from on-device EdgeTAM segmentation */
interface SweepCropInfo {
  /** GCS URL of the pre-cropped image */
  cropUrl: string;
  /** Bounding box [ymin, xmin, ymax, xmax] normalized 0-1000 */
  boundingBox: [number, number, number, number];
  /** Index of the keyframe this crop came from */
  frameIndex: number;
  /** Deduplication group ID from on-device segment grouping */
  groupId: string;
}

interface DetectedObject {
  groupId: string;
  label: string;
  category: string;
  attributes: Record<string, string>;
  confidence: 'high' | 'medium' | 'low';
  croppedImageUrls: string[];
  boundingBoxes: Array<{
    imageIndex: number;
    box_2d: [number, number, number, number];
  }>;
}
```

#### Sweep Mode

When `captureMode` is `"sweep"`, the session uses on-device EdgeTAM segmentation instead of server-side bounding box detection:

1. Client captures keyframes during camera sweep
2. EdgeTAM segments objects on-device, producing pre-cropped images
3. Client uploads crops to GCS and creates session with `sweepCrops` array
4. Cloud Function skips detection, labels pre-cropped segments via Gemini Flash
5. Results stored in `detectedObjects` (same schema as single/burst)

**Sweep-specific error codes:**
| Code | Description |
|------|-------------|
| `SWEEP_NO_CROPS` | Session has no sweep crops |
| `SWEEP_TOO_MANY_CROPS` | Exceeds 50 crop limit |
| `UNAUTHORIZED_BUCKET` | Crop URL from disallowed bucket |

| `lastRescanAt` | timestamp | No | Last rescan timestamp |
| `createdAt` | timestamp | Yes | Item creation timestamp |
| `updatedAt` | timestamp | Yes | Last update timestamp |
| `completedAt` | timestamp | No | AI processing completion timestamp |
| `deletedAt` | timestamp | No | Soft delete timestamp |
| `error` | string | No | Error message if failed |

#### Status Values

| Status | Description |
|--------|-------------|
| `pending` | Triggers AI processing (Gemini 3 Pro) |
| `layer2a_complete` | Layer 2a extraction complete |
| `layer2b_scheduled` | Layer 2b processing scheduled |
| `layer2b_complete` | Layer 2b processing complete |
| `complete` | All AI processing complete |
| `failed` | AI processing failed |
| `failed_layer2a` | Layer 2a specifically failed |
| `failed_layer2b` | Layer 2b specifically failed |

#### Condition Values

| Value | Description |
|-------|-------------|
| `new` | Brand new, unused |
| `like-new` | Minimal signs of use |
| `good` | Normal wear, fully functional |
| `fair` | Moderate wear, may have issues |
| `poor` | Heavy wear, may need repair |

#### Confidence Values

| Value | Numeric Equivalent | Description |
|-------|-------------------|-------------|
| `high` | 0.9 | High confidence identification |
| `medium` | 0.7 | Moderate confidence |
| `low` | 0.4 | Low confidence, may need verification |

## 4. Security Rules

Defined in `firestore.rules`:

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // Users can only read/write their own data
    match /users/{userId} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }

    // Items belong to users (row-level security)
    match /items/{itemId} {
      allow read: if request.auth != null && request.auth.uid == resource.data.userId;
      allow create: if request.auth != null && request.auth.uid == request.resource.data.userId;
      allow update, delete: if request.auth != null && request.auth.uid == resource.data.userId;
    }

    // Capture sessions belong to users (row-level security)
    match /sessions/{sessionId} {
      allow read: if request.auth != null && request.auth.uid == resource.data.userId;
      allow create: if request.auth != null && request.auth.uid == request.resource.data.userId;
      allow update, delete: if request.auth != null && request.auth.uid == resource.data.userId;
    }
  }
}
```

### Security Patterns

| Pattern | Description |
|---------|-------------|
| **Authentication Required** | All operations require `request.auth != null` |
| **Owner Verification (Read)** | `request.auth.uid == resource.data.userId` |
| **Owner Verification (Create)** | `request.auth.uid == request.resource.data.userId` |
| **User Data Isolation** | Users can only access documents where `userId` matches their UID |

### Cloud Function Access

Cloud Functions use Firebase Admin SDK which bypasses security rules. Functions validate:
- Session `userId` before processing
- Allowed storage buckets for image URLs
- Status transitions are valid

## 6. Cloud Function Triggers

### Session Processing (`onSessionCreated`)

**Trigger:** `sessions/{sessionId}` document updated
**Condition:** Status changes to `detecting` OR all images uploaded

**Flow:**
1. Validate session document (userId, image URLs)
2. Fetch images from GCS temp bucket
3. Call Gemini 3 Flash for object detection
4. Crop detected objects with sharp
5. Upload crops to permanent GCS bucket
6. Update session with `detectedObjects` array

### Item Cataloging (`onItemCreatedGemini3`)

**Trigger:** `items/{itemId}` document created
**Condition:** `status === 'pending'`

**Flow:**
1. Get signed URL for item image
2. Call Gemini 3 Pro with tool calling
3. Flatten catalog data to top-level fields
4. Update item with catalog results

```
        ▼

        │

   │
   ▼

   │
   ▼

   │
   ▼ (90 days)

```

```
[Created with status='uploading']
        │
        ▼

        │
        ▼

        │
   ┌────┴────┐
   ▼         ▼

   │
   ▼

```
