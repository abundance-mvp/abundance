## Executive Summary

This document defines the complete Firestore data model for Abundance MVP (Phase 1). The schema is optimized for:
- **Real-time sync** (iOS Firestore listeners)
- **Offline-first** (local persistence enabled by default)
- **Row-level security** (users only access their own data)
- **Scalable queries** (composite indexes for common patterns)

**Collections**: 3 top-level collections (users, items, subscriptions)
**Free Tier Compliance**: 1GB storage, 50K reads/day, 20K writes/day (verified sufficient for 5K users)

---

## Firestore Database Configuration

**Mode**: Native mode (not Datastore mode)
**Region**: us-central1 (matches Cloud Functions region)
**Offline Persistence**: Enabled by default on iOS SDK
**Security Rules**: Enforced via Firestore Security Rules (see SECURITY-RULES-001)

## Collection: `users`

### Purpose
User profiles and subscription status.

### Document ID
Firebase Auth UID (e.g., `firebase_user_abc123`)

### Schema

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `userId` | string | Yes | Firebase Auth UID (redundant but useful for queries) |
| `email` | string | No | User email (null if Apple Sign-In hides email) |
| `displayName` | string | No | User display name from Apple Sign-In |
| `subscriptionStatus` | string | Yes | "free" or "premium" |
| `subscriptionExpiresAt` | timestamp | No | Premium expiration date (null for free tier) |
| `catalogItemCount` | number | Yes | Total items cataloged (updated on item create/delete) |
| `createdAt` | timestamp | Yes | Account creation timestamp |
| `updatedAt` | timestamp | Yes | Last profile update timestamp |

### Indexes
None (queries by document ID only)

### Example Document (`users/firebase_user_abc123`)

```json
{
  "userId": "firebase_user_abc123",
  "email": "user@privaterelay.appleid.com",
  "displayName": "John Doe",
  "subscriptionStatus": "premium",
  "subscriptionExpiresAt": "2025-12-08T12:00:00Z",
  "catalogItemCount": 125,
  "createdAt": "2025-10-01T12:00:00Z",
  "updatedAt": "2025-11-08T10:30:00Z"
}
```

### Read Patterns

**Get user profile**:
```javascript
const userDoc = await db.collection('users').doc(userId).get();
const user = userDoc.data();
```

**Update catalog count** (on item create):
```javascript
await db.collection('users').doc(userId).update({
  catalogItemCount: admin.firestore.FieldValue.increment(1),
  updatedAt: admin.firestore.FieldValue.serverTimestamp()
});
```

## Collection: `items`

### Purpose
Catalog items with AI analysis results.

### Document ID
Auto-generated by Firestore (e.g., `item_12345abc`)

### Schema

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `userId` | string | Yes | Owner's Firebase Auth UID |
| `name` | string | Yes | Item name (user-editable) |
| `category` | string | Yes | Category (camping, tools, electronics, etc.) |
| `location` | string | No | Storage location (user-editable) |
| `imageURL` | string | Yes | Firebase Storage URL (cropped object image) |
| `barcode` | string | No | Barcode value (UPC, EAN, QR code) if detected |
| `aiAnalysis` | object | No | Nested object with Layer 1-3 AI results |
| `aiAnalysis.layer1` | object | Yes | On-device Vision results |
| `aiAnalysis.layer1.detectedClass` | string | Yes | Object class (tent, backpack, etc.) |
| `aiAnalysis.layer1.confidence` | number | Yes | Confidence score (0.0 - 1.0) |
| `aiAnalysis.layer1.boundingBox` | object | Yes | Bounding box {x, y, width, height} |
| `aiAnalysis.layer2a` | object | No | Gemini Vision attributes |
| `aiAnalysis.layer2a.color` | string | No | Primary color |
| `aiAnalysis.layer2a.material` | string | No | Material (polyester, metal, etc.) |
| `aiAnalysis.layer2a.condition` | string | No | Condition (new, excellent, good, fair, poor) |
| `aiAnalysis.layer2a.category` | string | No | AI-suggested category |
| `aiAnalysis.layer2b` | object | No | SerpAPI product identification |
| `aiAnalysis.layer2b.productName` | string | No | Product name from visual search |
| `aiAnalysis.layer2b.brand` | string | No | Brand name |
| `aiAnalysis.layer2b.model` | string | No | Model name |
| `aiAnalysis.layer2b.source` | string | No | "barcode" or "visual" |
| `aiAnalysis.layer2b.confidence` | number | No | Confidence score (0.0 - 1.0) |
| `aiAnalysis.layer3` | object | No | Claude synthesis |
| `aiAnalysis.layer3.estimatedValue` | number | No | Estimated market value (USD) |
| `aiAnalysis.layer3.confidence` | string | No | "high", "medium", or "low" |
| `aiAnalysis.layer3.reasoning` | string | No | AI reasoning for estimate |
| `status` | string | Yes | "processing", "complete", "failed" |
| `errorMessage` | string | No | Error message if status = "failed" |
| `createdAt` | timestamp | Yes | Item creation timestamp |
| `updatedAt` | timestamp | Yes | Last update timestamp |
| `deletedAt` | timestamp | No | Soft delete timestamp (null if not deleted) |

### Indexes

**Composite Index 1**: `userId` (ascending) + `createdAt` (descending)
- **Use case**: List user's items sorted by newest first
- **Query**: `db.collection('items').where('userId', '==', userId).orderBy('createdAt', 'desc')`

**Composite Index 2**: `userId` (ascending) + `category` (ascending)
- **Use case**: Filter user's items by category
- **Query**: `db.collection('items').where('userId', '==', userId).where('category', '==', 'camping')`

**Composite Index 3**: `userId` (ascending) + `status` (ascending)
- **Use case**: List user's pending items (processing or failed)
- **Query**: `db.collection('items').where('userId', '==', userId).where('status', '==', 'processing')`

**Composite Index 4**: `userId` (ascending) + `deletedAt` (ascending)
- **Use case**: List soft-deleted items for cleanup
- **Query**: `db.collection('items').where('userId', '==', userId).where('deletedAt', '!=', null)`

### Read Patterns

**List user's items** (paginated):
```javascript
const snapshot = await db.collection('items')
  .where('userId', '==', userId)
  .where('deletedAt', '==', null) // Exclude soft-deleted
  .orderBy('createdAt', 'desc')
  .limit(50)
  .get();

const items = snapshot.docs.map(doc => ({ id: doc.id, ...doc.data() }));
```

**Get single item**:
```javascript
const itemDoc = await db.collection('items').doc(itemId).get();
if (!itemDoc.exists) {
  throw new Error('Item not found');
}
const item = { id: itemDoc.id, ...itemDoc.data() };
```

**Filter by category**:
```javascript
const snapshot = await db.collection('items')
  .where('userId', '==', userId)
  .where('category', '==', 'camping')
  .where('deletedAt', '==', null)
  .orderBy('createdAt', 'desc')
  .get();
```

**Search by name** (client-side, no full-text search):
```javascript
// Note: Firestore doesn't support full-text search natively
// Fetch all items, filter client-side
const snapshot = await db.collection('items')
  .where('userId', '==', userId)
  .where('deletedAt', '==', null)
  .get();

const items = snapshot.docs
  .map(doc => ({ id: doc.id, ...doc.data() }))
  .filter(item => item.name.toLowerCase().includes(searchQuery.toLowerCase()));
```

### Write Patterns

**Create item**:
```javascript
const itemRef = await db.collection('items').add({
  userId,
  name: 'Untitled Item', // Placeholder until AI completes
  category: 'uncategorized',
  imageURL,
  barcode: detectedBarcode || null,
  aiAnalysis: { layer1: layer1Result },
  status: 'processing',
  createdAt: admin.firestore.FieldValue.serverTimestamp(),
  updatedAt: admin.firestore.FieldValue.serverTimestamp(),
  deletedAt: null
});

return itemRef.id;
```

**Update item** (Layer 2a complete):
```javascript
await db.collection('items').doc(itemId).update({
  'aiAnalysis.layer2a': layer2aResult,
  updatedAt: admin.firestore.FieldValue.serverTimestamp()
});
```

**Update item** (user edits name):
```javascript
await db.collection('items').doc(itemId).update({
  name: newName,
  updatedAt: admin.firestore.FieldValue.serverTimestamp()
});
```

**Soft delete item**:
```javascript
await db.collection('items').doc(itemId).update({
  deletedAt: admin.firestore.FieldValue.serverTimestamp(),
  status: 'deleted',
  updatedAt: admin.firestore.FieldValue.serverTimestamp()
});
```

**Hard delete item** (scheduled job, 90 days after soft delete):
```javascript
await db.collection('items').doc(itemId).delete();
```

## Collection: `subscriptions` (Phase 2)

### Purpose
Stripe subscription records for premium tier.

### Document ID
Stripe subscription ID (e.g., `sub_1A2B3C4D5E6F`)

### Schema

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `userId` | string | Yes | Owner's Firebase Auth UID |
| `stripeCustomerId` | string | Yes | Stripe customer ID |
| `status` | string | Yes | "active", "canceled", "past_due" |
| `currentPeriodEnd` | timestamp | Yes | Subscription expiration date |
| `cancelAtPeriodEnd` | boolean | Yes | True if user canceled (won't renew) |
| `createdAt` | timestamp | Yes | Subscription creation timestamp |
| `updatedAt` | timestamp | Yes | Last update timestamp |

### Indexes
None (queries by document ID or userId)

### Example Document (`subscriptions/sub_1A2B3C4D5E6F`)

```json
{
  "userId": "firebase_user_abc123",
  "stripeCustomerId": "cus_ABC123",
  "status": "active",
  "currentPeriodEnd": "2025-12-08T12:00:00Z",
  "cancelAtPeriodEnd": false,
  "createdAt": "2025-11-08T12:00:00Z",
  "updatedAt": "2025-11-08T12:00:00Z"
}
```

### Read Patterns

**Get user's subscription**:
```javascript
const snapshot = await db.collection('subscriptions')
  .where('userId', '==', userId)
  .where('status', '==', 'active')
  .limit(1)
  .get();

if (snapshot.empty) {
  return null; // Free tier
}

const subscription = { id: snapshot.docs[0].id, ...snapshot.docs[0].data() };
```

### Write Patterns

**Create subscription** (Stripe webhook):
```javascript
await db.collection('subscriptions').doc(stripeSubscriptionId).set({
  userId,
  stripeCustomerId,
  status: 'active',
  currentPeriodEnd: new Date(subscription.current_period_end * 1000),
  cancelAtPeriodEnd: false,
  createdAt: admin.firestore.FieldValue.serverTimestamp(),
  updatedAt: admin.firestore.FieldValue.serverTimestamp()
});

// Update user profile
await db.collection('users').doc(userId).update({
  subscriptionStatus: 'premium',
  subscriptionExpiresAt: new Date(subscription.current_period_end * 1000),
  updatedAt: admin.firestore.FieldValue.serverTimestamp()
});

// Set custom claim
await admin.auth().setCustomUserClaims(userId, { premium: true });
```

**Cancel subscription** (Stripe webhook):
```javascript
await db.collection('subscriptions').doc(stripeSubscriptionId).update({
  status: 'canceled',
  cancelAtPeriodEnd: true,
  updatedAt: admin.firestore.FieldValue.serverTimestamp()
});

// Downgrade user immediately (or at period end)
await db.collection('users').doc(userId).update({
  subscriptionStatus: 'free',
  subscriptionExpiresAt: null,
  updatedAt: admin.firestore.FieldValue.serverTimestamp()
});

await admin.auth().setCustomUserClaims(userId, { premium: false });
```

## Free Tier Compliance

### Storage Limits (Verified 2025-11-08)

**Free Tier**: 1GB storage

**MVP Projection** (5,000 users @ Month 6):
- Users collection: 5,000 docs × 0.5 KB = 2.5 MB
- Items collection: 250,000 docs × 2 KB = 500 MB
- **Total**: ~503 MB (50% of free tier)

**Conclusion**: ✅ MVP stays within free tier

### Read/Write Limits (Verified 2025-11-08)

**Free Tier**: 50,000 reads/day, 20,000 writes/day

**MVP Projection** (5,000 users @ Month 6):
- Reads: 5,000 users × 5 sessions/day × 1 catalog list query = 25,000 reads/day
- Writes: 5,000 users × 0.5 new items/day = 2,500 writes/day

**Conclusion**: ✅ MVP stays within free tier

**Risk**: Real-time listeners count as reads on every update. Monitor daily usage.

**Mitigation**:
- Implement client-side caching on iOS
- Use Firestore offline persistence (reduces redundant reads)
- Paginate queries (limit 50 items per page)

## Migration Strategy

### From MVP to Scale (10K+ users)

When exceeding free tier (likely Month 9-12):

**Option 1: Pay-as-you-go**
- Cost: $0.18/GB storage + $0.06/100K reads
- Acceptable for 10K-50K users

**Option 2: Optimize schema**
- Archive old items (soft-deleted > 90 days) to Cloud Storage (cheaper)
- Implement search index (Algolia, Typesense) for full-text search
- Reduce real-time listener usage (poll instead of subscribe)

**Option 3: Hybrid architecture**
- Keep Firestore for real-time catalog sync
- Move historical data to BigQuery (analytics)
- Use Cloud Storage for archived items
