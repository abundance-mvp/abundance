## Problem Statement

### Initial Errors

**XcodeGen Duplicate Filename Error:**
```
Filename "Animation+Extensions.swift" used twice:
  - '/Users/w/code/abundance-mvp-xcode/Abundance/App/Animation+Extensions.swift'
  - '/Users/w/code/abundance-mvp-xcode/Abundance/Sources/OnboardingFeature/Animation+Extensions.swift'
```

### Root Causes

1. **Code Duplication:** Identical design system files existed in multiple locations:
   - `Animation+Extensions.swift` (3 locations: App/, OnboardingFeature/, InventoryFeature/)
   - `Color+Extensions.swift` (3 locations: App/, OnboardingFeature/, InventoryFeature/)
   - `PrimaryButton.swift` (2 locations: OnboardingFeature/, InventoryFeature/)

2. **Architecture Mismatch:** Code written for multi-module SPM structure but compiled as single-target Xcode app
   - Files had `import OnboardingFeature`, `import VisionCore`, etc. (invalid in single-target)
   - Used `Bundle.module` (SPM-only, not available in single-target apps)
   - Multiple `PlatformImage` typealias declarations conflicted in single module

3. **Resource Path Issues:** Regeneration script inconsistencies
   - Script restored `GoogleService-Info.plist` to root but project.yml referenced `App/GoogleService-Info.plist`

## Solution Architecture

### 1. Design System Consolidation

**Approach:** Create centralized Core layer following 2025 modular architecture best practices.

#### New Structure
```
Sources/
├── Core/
│   ├── DesignSystem/
│   │   ├── Components/
│   │   │   └── PrimaryButton.swift          # Single source for button component
│   │   └── Extensions/
│   │       ├── Animation+Brand.swift        # Brand animation presets
│   │       └── Color+Brand.swift            # Brand color system
│   └── Logging/
│       └── AppLogger.swift
├── CameraFeature/
├── OnboardingFeature/
├── InventoryFeature/
├── Persistence/
└── VisionCore/
```

#### Rationale
- **DRY Principle:** Single source of truth for shared UI components
- **Layer-Based Architecture:** Core layer supports all feature layers
- **Naming Clarity:** `Animation+Brand.swift` and `Color+Brand.swift` clearly indicate brand-specific extensions
- **Scalability:** Easy to add more design system components (Typography, Spacing, etc.)
- **Maintainability:** Single update propagates to all features

### 2. Single-Target App Architecture Fixes

**Context:** This is a **single-target Xcode app** where all code compiles into one "Abundance" module. Unlike multi-module SPM setups, there are no separate feature modules.

#### Bundle Reference Fixes

**Changed SPM-specific `Bundle.module` → `Bundle.main`:**

```swift
// ❌ BEFORE (SPM-only)
guard let modelURL = Bundle.module.url(forResource: "yolo11n", withExtension: "mlmodelc")

// ✅ AFTER (single-target app)
guard let modelURL = Bundle.main.url(forResource: "yolo11n", withExtension: "mlmodelc")
```

**Files Modified:**
- `Sources/VisionCore/Services/HouseholdItemDetector.swift` (2 occurrences)

**Rationale:** `Bundle.module` is auto-generated by SPM for package resources. In single-target Xcode apps, all resources are in `Bundle.main`.

#### PlatformImage Typealias Deduplication

**Problem:** Three files declared the same typealias, causing redeclaration errors in single module:
```swift
// All three files had this:
#if os(iOS)
public typealias PlatformImage = UIImage
#elseif os(macOS)
public typealias PlatformImage = NSImage
#endif
```

**Solution:** Keep canonical definition in `VisionCore/Utilities/PlatformTypes.swift`, remove from:
- `Sources/CameraFeature/ViewModels/CameraViewModel.swift` ❌ (removed typealias, kept UIKit import)
- `Sources/Persistence/Firebase/StorageService.swift` ❌ (removed typealias, kept UIKit import)

**Important:** Kept `#if os(iOS) import UIKit` in files that use `UIImage` directly - only removed duplicate `typealias` declarations.

### 3. Swift 6 Strict Concurrency Fixes

**Problem:** Static singletons flagged as non-Sendable in strict concurrency mode.

```swift
// ❌ BEFORE
class LogFileWriter {
    static let shared = LogFileWriter()  // ⚠️ Not concurrency-safe
}

// ✅ AFTER
class LogFileWriter {
    nonisolated(unsafe) static let shared = LogFileWriter()
}
```

**Files Modified:**
- `Sources/Core/Logging/AppLogger.swift` (2 occurrences: LogFileWriter, FirebaseLogger)

**Rationale:** `nonisolated(unsafe)` indicates these singletons are thread-safe through internal synchronization (DispatchQueue), suppressing Swift 6 warnings without disabling strict concurrency.

### 4. Regeneration Script Fixes

**Updated:** `scripts/regenerate-xcode-project.sh`

**Changes:**
```bash
# Backup section (line 83)
if [ -f "$XCODE_ROOT/App/GoogleService-Info.plist" ]; then

# Restore section (lines 165, 169)
cp "$BACKUP_DIR/GoogleService-Info.plist" "$XCODE_ROOT/App/GoogleService-Info.plist"
cp "$PROJECT_ROOT/App/GoogleService-Info.plist" "$XCODE_ROOT/App/GoogleService-Info.plist"
```

**project.yml Update:**
```yaml
resources:
  - App/Assets.xcassets
  - App/GoogleService-Info.plist  # ✅ Correct path
  - Sources/VisionCore/Resources/yolo11n.mlmodelc
```

**Rationale:** Ensures GoogleService-Info.plist is restored to `App/` directory where XcodeGen expects it based on project.yml configuration.

## Firebase XCFrameworks Repository

### Why We Use `akaffenberger/firebase-ios-sdk-xcframeworks`

**Repository:** https://github.com/akaffenberger/firebase-ios-sdk-xcframeworks
**Version:** 12.6.0
**Type:** Binary XCFrameworks (pre-compiled)

### Rationale

**Primary Reason:** **Xcode Beta Compatibility**

The official Firebase iOS SDK (source-based SPM) has compilation issues with Xcode beta versions due to:
1. **swift-protobuf compilation errors** in beta Swift toolchains
2. **Strict concurrency warnings** treated as errors in beta
3. **New compiler optimizations** breaking legacy C++ bridging code

**Benefits of XCFrameworks:**
- ✅ Pre-compiled binaries bypass swift-protobuf compilation
- ✅ Work immediately with Xcode beta releases
- ✅ Faster build times (no recompilation of Firebase dependencies)
- ✅ Smaller package resolution size (direct binary downloads vs source)
- ✅ Same API surface as official SDK (drop-in replacement)

**Trade-offs:**
- ⚠️ Community-maintained (not official Anthropic/Google)
- ⚠️ Slight version lag (~1-2 weeks) behind official releases
- ⚠️ Larger binary artifact cache (stored in `~/Library/Developer/Xcode/DerivedData`)

**Configuration:**
```yaml
# project.yml
packages:
  firebase-ios-sdk:
    url: https://github.com/akaffenberger/firebase-ios-sdk-xcframeworks.git
    from: 12.6.0
```

**Alternative:** Switch back to official SDK once on stable Xcode:
```yaml
# For stable Xcode (when beta issues resolved)
packages:
  firebase-ios-sdk:
    url: https://github.com/firebase/firebase-ios-sdk.git
    from: 11.8.0
```

## Best Practices Applied

### 1. DRY (Don't Repeat Yourself)
- ✅ Single source of truth for design system components
- ✅ Eliminates maintenance burden of syncing 8 duplicate files

### 2. Separation of Concerns
- ✅ Core layer contains shared utilities (design system, logging)
- ✅ Feature layers (Camera, Inventory, Onboarding) depend on Core
- ✅ Clear dependency direction: Features → Core (never Core → Features)

### 3. Naming Conventions
- ✅ `Animation+Brand.swift` clearly indicates brand-specific extensions (vs generic Animation+Utilities.swift)
- ✅ `PrimaryButton` follows SwiftUI component naming (vs GenericButton, StyledButton)

### 4. Swift 6 Strict Concurrency
- ✅ Enabled `ENABLE_STRICT_CONCURRENCY_CHECKING: YES`
- ✅ Applied `nonisolated(unsafe)` to legacy singletons (not ideal, but pragmatic)
- ✅ Future work: Migrate to Swift 6 actor-based singletons

### 5. Documentation
- ✅ Comprehensive inline comments explaining architecture decisions
- ✅ WCAG contrast ratios documented in Color+Brand.swift
- ✅ Animation timing values documented with use cases
