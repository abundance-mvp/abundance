## Architecture Decisions Summary

### 1. Firestore Data Model

**Collections**:
- `users/{userId}` - User profiles, subscription status
- `items/{itemId}` - Catalog items with AI analysis results
- `subscriptions/{subscriptionId}` - Stripe subscription records (Phase 2)

**Key Design Decisions**:
- Top-level collections (not nested subcollections) for simpler queries
- Composite indexes for common queries (userId + createdAt, userId + category)
- Offline-first support (Firestore local persistence enabled by default)
- Real-time sync via Firestore listeners

**Verified Constraints**:
- Free tier: 1GB storage, 50K reads/day, 20K writes/day (sufficient for MVP)
- Pricing: $0.18/GB storage, $0.06/100K reads (verified 2025-11-08)

**Deliverable**: `DATA-MODEL-001-firestore-schema.md`

---

### 2. Cloud Functions Architecture

**Function Categories**:

**HTTP Endpoints** (8 functions):
- Health check (no auth)
- Create/get/list/update/delete items (require auth)
- Get user profile (require auth)
- Stripe webhook (Stripe signature verification)

**Firestore Triggers** (3 functions):
- `onItemCreated` → Launch Layer 2a (Gemini attribute extraction)
- `onLayer2aComplete` → Launch Layer 2b (SerpAPI product ID)
- `onLayer2bComplete` → Launch Layer 3 (Claude synthesis)

**Scheduled Jobs** (2 functions):
- `cleanupDeletedItems` - Daily at 2am UTC (soft-deleted items > 90 days)
- `checkSubscriptionExpiry` - Daily at 6am UTC (downgrade expired premium users)

**Verified Constraints**:
- Free tier: 2 million invocations/month (sufficient for MVP)
- Pricing: $0.40/million invocations + compute costs (vCPU-seconds, GiB-seconds)
- Runtime: Node.js 20 (production-ready, verified 2025-11-08)

**Deliverable**: `CLOUD-FUNCTIONS-001-function-structure.md`

### 3. Firestore Security Rules

**Row-Level Security**:
- Users can only read/write their own data (`request.auth.uid == resource.data.userId`)
- Premium status enforced via custom claims (`request.auth.token.premium == true`)
- Admin operations (subscriptions) restricted to Cloud Functions only

**Example Rule**:
```javascript
match /items/{itemId} {
  allow read: if isSignedIn() && resource.data.userId == request.auth.uid;
  allow create: if isSignedIn() && request.resource.data.userId == request.auth.uid;
}
```

**Deliverable**: `SECURITY-RULES-001-firestore-rules.md`

---

### 4. Firebase Storage Rules

**Access Control**:
- Users can only upload to their own user folder (`users/{userId}/items/{itemId}/*.jpg`)
- 10MB file size limit per upload
- Uploaded images are private (no public read)
- SerpAPI accesses images via signed URLs (time-limited, generated by Cloud Functions)

**Signed URL Strategy**:
- Token-based URLs for iOS app downloads (persistent)
- Time-limited URLs for SerpAPI (1-hour expiration)

**Verified Constraints**:
- Pricing: $0.020/GB for Standard class in us-central1 (verified 2025-11-08)
- Signed URLs: Both token-based and time-limited supported (verified)

**Deliverable**: `STORAGE-RULES-001-firebase-storage-rules.md`

### 5. AI Pipeline Orchestration

**Cloud AI Flow**:
```
iOS (Layer 1: On-device Vision)
  ↓
Cloud Functions (Layer 2-3):
  1. onItemCreated → Gemini Vision (Layer 2a: attributes)
  2. onLayer2aComplete → SerpAPI (Layer 2b: product ID)
  3. onLayer2bComplete → Claude Batch API (Layer 3: synthesis)
  4. onLayer3Complete → Update item status = "complete"
```

**AI Providers**:
- **Layer 2a**: Vertex AI Gemini 2.0 Flash-Exp ($0.000249/image, JSON Schema Mode)
- **Layer 2b**: SerpAPI Google Lens ($0.015/search, Developer Plan $75/month)
- **Layer 3**: Anthropic Claude Sonnet 4.5 Batch API ($0.002027/inference, 50% discount)

**Error Handling**:
- Each layer wrapped in try/catch
- Failures mark item as `status: "failed"` with error message
- Retry logic NOT implemented in MVP (manual retry via re-upload)

**Verified Constraints**:
- Gemini pricing verified (2025-11-08)
- SerpAPI Google Lens API verified (2025-11-08)
- Claude Batch API pricing verified (2025-11-08)

**Deliverable**: `AI-INTEGRATION-LAYER-001-cloud-ai-orchestration.md`

### 6. Deployment Architecture

**Environments**:
- **Development**: `abundance-dev` (Firebase Emulator Suite + local functions)
- **Staging**: `abundance-staging` (pre-production testing, TestFlight backend)
- **Production**: `abundance-prod` (live users, App Store backend)

**CI/CD Pipeline** (GitHub Actions):
1. PR merged to `main` → Run tests
2. Tests pass → Deploy to staging
3. Staging validated → Deploy to production
4. Production deployed → Smoke tests

**Monitoring**:
- Cloud Logging (all function logs → BigQuery export)
- Cloud Monitoring (latency, error rate dashboards)
- Alert policies (>5% error rate, >2s P95 latency)
- Cost monitoring (budget alerts at 50%, 90%, 100%)

**Rollback Strategy**:
- Cloud Functions versioning (rollback to previous deployment)
- Firestore point-in-time recovery (up to 7 days)

## Risks Identified

### Risk 1: Firestore Free Tier Daily Limits
- **Impact**: High (exceeding 50K reads/day triggers pay-as-you-go)
- **Probability**: Medium (iOS app uses real-time listeners, high read volume)
- **Mitigation**: Implement daily usage monitoring, optimize query patterns, cache aggressively on iOS

### Risk 2: Cloud Functions Cold Starts
- **Impact**: Medium (first request after idle = 1-3s latency)
- **Probability**: High (serverless architecture has inherent cold starts)
- **Mitigation**: Use Cloud Functions 2nd gen (faster cold starts), implement minimum instances for critical endpoints

### Risk 3: AI Pipeline Failures
- **Impact**: High (items stuck in "processing" state if Layer 2-3 fail)
- **Probability**: Medium (SerpAPI/Gemini/Claude API timeouts, quota limits)
- **Mitigation**: Implement exponential backoff retry, dead letter queue for failed items, manual retry UI

### Risk 4: Cloud CDN Costs Higher Than Expected
- **Impact**: Medium (CDN egress pricing is tiered, not flat)
- **Probability**: Low (MVP traffic is small)
- **Mitigation**: Monitor CDN usage, use blended $0.08/GB estimate for planning, implement caching on iOS
