## Commit Message Format

Use [Conventional Commits](https://www.conventionalcommits.org/):

```
<type>(<scope>): <description>

[optional body]

[optional footer]
```

**Types:**
- `feat:` New feature
- `fix:` Bug fix
- `docs:` Documentation only
- `style:` Code style changes (formatting)
- `refactor:` Code refactoring
- `test:` Adding/updating tests
- `chore:` Maintenance tasks

**Examples:**
```
feat(onboarding): add biometric authentication
fix(backend): resolve Firestore query timeout
docs: update setup guide for Xcode 16
```

## Testing Guidelines

### Test-Driven Development (TDD)

**Required workflow:**
1. Write failing test
2. Run test to verify it fails
3. Write minimal code to pass test
4. Run test to verify it passes
5. Refactor if needed
6. Commit

**Example:**
```swift
// 1. Write failing test
func testSignInWithValidCredentials() {
    let result = viewModel.signIn(email: "test@example.com", password: "pass123")
    XCTAssertTrue(result.isSuccess)
}

// 2. Run: swift test (FAILS - signIn not implemented)

// 3. Implement minimal code
func signIn(email: String, password: String) -> Result<User, Error> {
    // Minimal implementation
}

// 4. Run: swift test (PASSES)
// 5. Commit
```

## ADR Compliance

**All code changes must comply with Architecture Decision Records.**

**Check compliance:**
```bash
/check-drift
```

**Severity levels:**
- **P0:** Architectural violations (BLOCKS PR)
- **P1:** Best practice violations (requires justification)
- **P2:** Style/convention violations (warnings)

**Common violations:**
- `import UIKit` → P0 (violates ADR-010 SwiftUI-only)
- Unauthorized dependencies → P1
- Naming convention violations → P2
