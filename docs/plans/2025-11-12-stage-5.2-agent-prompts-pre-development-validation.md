**Step 1: Write git branching strategy**

Create file documenting:
- Branch structure (main → feature/sprint-X-description)
- Git worktree workflow (using superpowers:using-git-worktrees)
- Commit message format (`feat(scope): description`)
- Branch protection rules for main
- Sprint branch lifecycle (create → implement → PR → merge → delete)

**Example structure**:
```markdown
# DEVELOPMENT-WORKFLOW-001: Git Branching Strategy

## Branch Structure
main (protected)
├── feature/sprint-1-project-setup
├── feature/sprint-2-camera-layer-1
└── [... sprint branches ...]

## Workflow
1. Create feature branch: `git checkout -b feature/sprint-X-description`
2. Or use worktree (recommended): `git worktree add ../abundance-sprint-X -b feature/sprint-X-description`
3. Implement sprint tasks (TDD workflow via Superpowers)
4. Create PR: `gh pr create --title "Sprint X: Description"`
5. Merge via GitHub (squash + merge)
6. Cleanup: `git worktree remove ../abundance-sprint-X` (if using worktrees)

## Commit Message Format
<type>(scope): <description>

Types: feat, fix, refactor, test, docs
Scopes: ios, backend, ai-pipeline, auth, camera, catalog
Description: imperative mood, < 50 chars

Examples:
- feat(auth): implement Apple Sign-In with Firebase integration
- fix(camera): resolve AVCaptureSession memory leak
- test(catalog): add CatalogViewModelTests for search

## Branch Protection (main)
- Require PR before merging
- Require status checks to pass (CI/CD)
- No force pushes
- No deletions

## Why Git Worktrees?
Isolates each sprint in separate workspace:
- No context switching overhead (`git checkout` switches entire directory)
- Parallel sprint work possible
- Clean separation of concerns

Example: Work on Sprint 2 while Sprint 1 PR is in review
```

**Step 1: Write sprint execution guide**

Document 7-phase sprint lifecycle that ios-sprint-executor follows:
```markdown
# DEVELOPMENT-WORKFLOW-003: Sprint Execution Guide

## Sprint Lifecycle (via ios-sprint-executor)

```
SETUP → PLAN → APPROVE → EXECUTE → REVIEW → PR → CLEANUP
```

## Phase 1: Setup (ios-sprint-executor Phase 1)
- Load sprint plan: docs/roadmap/SPRINT-PLAN-00X.md
- Detect iOS work (Vision, SwiftUI, AVFoundation keywords)
- Fetch Apple docs (if iOS work detected, using apple-docs-fetcher)
- Create git worktree (optional): `../abundance-sprint-X/`
- Create feature branch: `feature/sprint-X-description`

## Phase 2: Planning (ios-sprint-executor Phase 2)
- Load context documents (ADRs, DESIGN docs, CODE-EXAMPLEs from sprint plan)
- Invoke /superpowers:write-plan with enhanced instructions
- Generate implementation plan (tasks, batches, token budget)

## Gate 1: Human Approval
- Review implementation plan
- Type 'proceed' to continue or 'revise plan: [feedback]' to regenerate

## Phase 3: Execution (ios-sprint-executor Phase 3)
- Invoke /superpowers:execute-plan with implementation plan
- Execute in batches with review checkpoints
- Follow TDD workflow (test first, watch fail, implement, watch pass)
- Cross-reference documentation in code comments

## Phase 4: Code Review (ios-sprint-executor Phase 4)
- Invoke superpowers:requesting-code-review
- Address feedback if issues found
- Re-run tests, re-run code review

## Phase 5: PR Creation (ios-sprint-executor Phase 5)
- Commit changes with proper message format
- Push branch: `git push -u origin feature/sprint-X-description`
- Create PR using template from DEVELOPMENT-WORKFLOW-002
- Display PR link and summary

## Phase 6: Completion (ios-sprint-executor Phase 6)
- Display completion banner with summary
- Optional: Clean up git worktree after PR merged

## Usage

To execute a sprint:
```
/ios-sprint-executor sprint-1
/ios-sprint-executor sprint-2
...
```

The skill handles all phases automatically with human approval gates.
```
