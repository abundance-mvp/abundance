### Task 1: Firestore Data Model Design

**Objective**: Define complete Firestore schema (collections, documents, indexes)

**Acceptance Criteria**:
- Given the iOS client data models (DESIGN-011)
- When mapping to Firestore collections
- Then create schema that supports:
  - Real-time sync (Firestore listeners)
  - Offline-first (local persistence)
  - Row-level security (user-owned data)
  - Scalable queries (composite indexes)

**Deliverable**: `docs/tech-stack/DATA-MODEL-001-firestore-schema.md`

**Schema Requirements**:

1. **`users` collection**:
   - Document ID: Firebase Auth UID
   - Fields: `email` (optional), `displayName`, `subscriptionStatus` (free/premium), `createdAt`, `updatedAt`
   - Indexes: None (query by document ID only)

2. **`items` collection**:
   - Document ID: Auto-generated (Firestore)
   - Fields: `userId`, `name`, `category`, `imageURL`, `barcode`, `aiAnalysis` (nested object), `status` (processing/complete), `createdAt`, `updatedAt`
   - Indexes:
     - Composite: `userId` + `createdAt` (for catalog list sorted by date)
     - Composite: `userId` + `category` (for category filtering)
     - Composite: `userId` + `status` (for pending items)

3. **`subscriptions` collection** (Phase 2):
   - Document ID: Stripe subscription ID
   - Fields: `userId`, `status` (active/canceled), `currentPeriodEnd`, `createdAt`

### Task 2: Cloud Functions Structure

**Objective**: Design Cloud Functions architecture (HTTP endpoints, triggers, scheduled jobs)

**Acceptance Criteria**:
- Given API-CONTRACTS-001 endpoint specifications
- When implementing Cloud Functions
- Then create functions that:
  - Match exact REST API contracts
  - Verify Firebase Auth tokens
  - Handle errors consistently
  - Log to Cloud Logging

**Deliverable**: `docs/design/CLOUD-FUNCTIONS-001-function-structure.md`

**Function Categories**:

1. **HTTP Endpoints** (REST API):
   - `api-health` - GET /api/v1/health (no auth)
   - `api-createItem` - POST /api/v1/items (requires auth)
   - `api-getItem` - GET /api/v1/items/:itemId (requires auth)
   - `api-listItems` - GET /api/v1/items (requires auth, pagination)
   - `api-updateItem` - PUT /api/v1/items/:itemId (requires auth)
   - `api-deleteItem` - DELETE /api/v1/items/:itemId (requires auth)
   - `api-getUser` - GET /api/v1/users/:userId (requires auth)
   - `api-subscriptionWebhook` - POST /api/v1/subscriptions/webhook (Stripe signature)

2. **Firestore Triggers** (AI Pipeline):
   - `onItemCreated` - Trigger Layer 2a (Gemini attribute extraction)
   - `onLayer2aComplete` - Trigger Layer 2b (SerpAPI product ID)
   - `onLayer2bComplete` - Trigger Layer 3 (Claude synthesis)

3. **Scheduled Jobs**:
   - `cleanupDeletedItems` - Daily at 2am UTC (delete soft-deleted items > 90 days)
   - `checkSubscriptionExpiry` - Daily at 6am UTC (downgrade expired premium users)

**Function Template** (Node.js 20):
```javascript
const functions = require('firebase-functions/v2');
const admin = require('firebase-admin');

// HTTP endpoint with auth
exports.api_createItem = functions.https.onCall(async (data, context) => {
  // Verify auth
  if (!context.auth) {
    throw new functions.https.HttpsError('unauthenticated', 'User must be signed in');
  }

  const userId = context.auth.uid;
  const { imageURL, layer1Result, detectedBarcode } = data;

  // Validate inputs
  if (!imageURL || !layer1Result) {
    throw new functions.https.HttpsError('invalid-argument', 'Missing required fields');
  }

  // Create Firestore document
  const itemRef = await admin.firestore().collection('items').add({
    userId,
    imageURL,
    aiAnalysis: { layer1: layer1Result },
    barcode: detectedBarcode || null,
    status: 'processing',
    createdAt: admin.firestore.FieldValue.serverTimestamp()
  });

  // Return item ID
  return { itemId: itemRef.id, status: 'processing' };
});

// Firestore trigger (AI pipeline)
exports.onItemCreated = functions.firestore
  .document('items/{itemId}')
  .onCreate(async (snap, context) => {
    const item = snap.data();
    const itemId = context.params.itemId;

    // Call Gemini API (Layer 2a)
    const layer2aResult = await callGeminiVision(item.imageURL);

    // Update item with Layer 2a results
    await snap.ref.update({
      'aiAnalysis.layer2a': layer2aResult,
      updatedAt: admin.firestore.FieldValue.serverTimestamp()
    });
  });
```

### Task 3: Firestore Security Rules

**Objective**: Define Firestore security rules (row-level access control)

**Acceptance Criteria**:
- Given Firestore data model
- When users access collections
- Then enforce:
  - Users can only read/write their own data
  - Premium status checked for gated features
  - Admin functions have elevated access

**Deliverable**: `docs/design/SECURITY-RULES-001-firestore-rules.md`

**Security Rules Template**:
```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Helper functions
    function isSignedIn() {
      return request.auth != null;
    }

    function isOwner(userId) {
      return isSignedIn() && request.auth.uid == userId;
    }

    function isPremium() {
      return isSignedIn() && request.auth.token.premium == true;
    }

    // Users collection
    match /users/{userId} {
      allow read: if isOwner(userId);
      allow write: if isOwner(userId);
    }

    // Items collection
    match /items/{itemId} {
      allow read: if isSignedIn() && resource.data.userId == request.auth.uid;
      allow create: if isSignedIn() && request.resource.data.userId == request.auth.uid;
      allow update, delete: if isSignedIn() && resource.data.userId == request.auth.uid;
    }

    // Subscriptions collection (admin only)
    match /subscriptions/{subscriptionId} {
      allow read: if isSignedIn() && resource.data.userId == request.auth.uid;
      allow write: if false; // Only Cloud Functions can write
    }
  }
}
```

### Task 4: Firebase Storage Rules

**Objective**: Define Firebase Storage security rules (image access control)

**Acceptance Criteria**:
- Given image storage architecture (ADR-008)
- When users upload/download images
- Then enforce:
  - Users can only upload to their own user folder
  - Uploaded images are private (no public read)
  - SerpAPI receives signed URLs (time-limited)

**Deliverable**: `docs/design/STORAGE-RULES-001-firebase-storage-rules.md`

**Storage Rules Template**:
```javascript
rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {

    // Helper functions
    function isSignedIn() {
      return request.auth != null;
    }

    function isOwner(userId) {
      return isSignedIn() && request.auth.uid == userId;
    }

    // User images: users/{userId}/items/{itemId}/*.jpg
    match /users/{userId}/items/{itemId}/{fileName} {
      allow read: if isOwner(userId);
      allow write: if isOwner(userId) && request.resource.size < 10 * 1024 * 1024; // 10MB limit
    }

    // Processed images (AI pipeline): processed/{itemId}/*.jpg
    match /processed/{itemId}/{fileName} {
      allow read: if false; // Only accessible via signed URLs
      allow write: if false; // Only Cloud Functions can write
    }
  }
}
```

**Signed URL Generation** (Cloud Functions):
```javascript
const { getStorage } = require('firebase-admin/storage');

async function generateSignedUrl(imagePath, expiresIn = 3600) {
  const bucket = getStorage().bucket();
  const file = bucket.file(imagePath);

  const [url] = await file.getSignedUrl({
    version: 'v4',
    action: 'read',
    expires: Date.now() + expiresIn * 1000 // 1 hour default
  });

  return url;
}
```

### Task 5: AI Pipeline Orchestration

**Objective**: Design AI pipeline orchestration (Layer 2-3 cloud AI)

**Acceptance Criteria**:
- Given 4-layer AI pipeline (DESIGN-004)
- When item is created with Layer 1 results
- Then orchestrate:
  - Layer 2a: Gemini Vision (attribute extraction)
  - Layer 2b: SerpAPI (product identification)
  - Layer 3: Claude Batch API (synthesis)

**Deliverable**: `docs/design/AI-INTEGRATION-LAYER-001-cloud-ai-orchestration.md`

**AI Pipeline Flow**:
```
iOS (Layer 1: On-device Vision) → Cloud Functions (Layer 2-3)

1. onItemCreated trigger → Layer 2a (Gemini)
2. onLayer2aComplete trigger → Layer 2b (SerpAPI)
3. onLayer2bComplete trigger → Layer 3 (Claude)
4. onLayer3Complete → Update item status to "complete"
```

**Layer 2a: Gemini Vision (Attribute Extraction)**:
```javascript
const { VertexAI } = require('@google-cloud/vertexai');

async function extractAttributes(imageURL) {
  const vertex_ai = new VertexAI({ project: 'abundance-prod', location: 'us-central1' });
  const model = 'gemini-2.0-flash-exp';

  const generativeModel = vertex_ai.preview.getGenerativeModel({
    model: model,
    generationConfig: {
      maxOutputTokens: 256,
      temperature: 0.2,
      responseMimeType: 'application/json',
      responseSchema: {
        type: 'object',
        properties: {
          color: { type: 'string' },
          material: { type: 'string' },
          condition: { type: 'string', enum: ['new', 'excellent', 'good', 'fair', 'poor'] },
          category: { type: 'string' }
        }
      }
    }
  });

  const request = {
    contents: [{
      role: 'user',
      parts: [
        { fileData: { mimeType: 'image/jpeg', fileUri: imageURL } },
        { text: 'Extract the color, material, condition, and category of this object.' }
      ]
    }]
  };

  const response = await generativeModel.generateContent(request);
  return JSON.parse(response.response.candidates[0].content.parts[0].text);
}
```

**Layer 2b: SerpAPI (Product Identification)**:
```javascript
const axios = require('axios');

async function identifyProduct(imageURL) {
  const response = await axios.get('https://serpapi.com/search', {
    params: {
      engine: 'google_lens',
      url: imageURL,
      api_key: process.env.SERPAPI_KEY
    }
  });

  const visualMatches = response.data.visual_matches || [];
  if (visualMatches.length === 0) {
    return { productName: null, source: 'visual', confidence: 0 };
  }

  return {
    productName: visualMatches[0].title,
    source: 'visual',
    confidence: visualMatches[0].position === 1 ? 0.92 : 0.75
  };
}
```

**Layer 3: Claude Batch API (Synthesis)**:

```javascript
const Anthropic = require('@anthropic-ai/sdk');

async function synthesizeMetadata(layer2aResult, layer2bResult) {
  const anthropic = new Anthropic({ apiKey: process.env.ANTHROPIC_API_KEY });

  const prompt = `
You are an AI assistant that synthesizes product metadata.

Layer 2a (Attributes): ${JSON.stringify(layer2aResult)}
Layer 2b (Product ID): ${JSON.stringify(layer2bResult)}

Synthesize this information and provide:
1. Estimated market value (USD)
2. Confidence level (high/medium/low)
3. Reasoning for the estimate

Return JSON format:
{
  "estimatedValue": number,
  "confidence": "high" | "medium" | "low",
  "reasoning": "string"
}
`;

  const message = await anthropic.messages.create({
    model: 'claude-sonnet-4-20250514',
    max_tokens: 512,
    messages: [{ role: 'user', content: prompt }]
  });

  return JSON.parse(message.content[0].text);
}
```

### Task 7: ADR-019: Firestore Data Model Rationale

**Objective**: Document rationale for Firestore data model design

**Acceptance Criteria**:
- Given Firestore schema (Task 1)
- When comparing to alternatives (SQL, MongoDB)
- Then document:
  - Why NoSQL over SQL
  - Why Firestore over DynamoDB/MongoDB
  - Collection structure rationale
  - Index strategy

**Deliverable**: `docs/adr/ADR-019-firestore-data-model-rationale.md`

**Decision Summary**:
- **NoSQL over SQL**: Real-time sync, offline-first, flexible schema
- **Firestore over DynamoDB**: Firebase ecosystem integration, simpler security rules
- **Firestore over MongoDB**: Managed service, automatic scaling, Firebase SDK
- **Collection structure**: Top-level collections (not nested subcollections) for simpler queries
- **Index strategy**: Composite indexes for common query patterns (userId + createdAt)
