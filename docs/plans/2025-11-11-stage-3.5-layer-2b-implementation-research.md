## Background & Context

### What This Stage Accomplishes

Stage 3.5 bridges the gap between Layer 2b architectural specifications (Stage 2.4) and actual backend implementation by providing **production-ready code examples** for the complete product search pipeline. With backend patterns documented (Stage 3.2) and research verification complete (RESEARCH-VALIDATION-stage-3.5), this stage creates the Layer 2b implementation playbook.

**Layer 2b = Product Search**:
1. **Barcode-first strategy**: OpenFoodFacts (free) → UPCitemdb ($99/month) → SerpAPI visual fallback
2. **Visual search**: SerpAPI Google Lens API ($0.015 per search)
3. **LLM parsing**: Claude Haiku 4.5 ($0.001 per parse) extracts brand/model/variant
4. **Orchestration**: Cloud Functions Node.js 20 coordinates barcode → visual → parsing flow

### Why This Stage Is Critical

**Problem**: Previous stages defined WHAT to build (ADR-018, DESIGN-018, DESIGN-019), but not HOW to implement with production-ready patterns.

**Gap**: AI agents need:
- Working code examples (not pseudo-code)
- Error handling patterns (retry, fallback, dead letter queue)
- Cost optimization patterns (barcode-first to reduce API costs by 22.6%)
- Testing patterns (mocking external APIs, integration tests)

**Solution**: Stage 3.5 delivers 4-5 CODE-EXAMPLE documents with complete, compilable Node.js 20 implementations.

**Stage 3.2 (Backend Implementation Research)**:
- Established Cloud Functions patterns (async/await, error handling, Firestore triggers)

- **Stage 3.5 builds on**: These patterns are adapted for Layer 2b product search

## Implementation Tasks (Detailed, with Test Examples)

### Task 1: Implement Hybrid Barcode Lookup Service

**Objective**: Create Node.js 20 service that tries OpenFoodFacts → UPCitemdb → SerpAPI in sequence

**Acceptance Criteria (Given/When/Then)**:
- **Given** a barcode value (e.g., `049000050103` for Coca-Cola)
- **When** hybrid lookup is called
- **Then** OpenFoodFacts is tried first (free)
- **And** UPCitemdb is tried if OpenFoodFacts fails
- **And** SerpAPI visual search is used as final fallback
- **And** response includes `source` field ('openfoodfacts', 'upcitemdb', 'serpapi')

**Test Example**:
```javascript
// Given
const barcodeData = { value: '049000050103', type: 'EAN-13' };

// When
const result = await lookupBarcodeHybrid(barcodeData, 'item_123');

// Then
expect(result.found).toBe(true);
expect(result.source).toBe('openfoodfacts'); // Free tier hit
expect(result.name).toContain('Coca-Cola');
```

**Code Deliverable**: `CODE-EXAMPLE-012-barcode-hybrid-lookup.md`

**Implementation Notes**:
- Use `node-fetch` for REST API calls (Node.js 20 native fetch)
- Implement exponential backoff for UPCitemdb rate limits (429 errors)
- Log usage to Firestore `barcode_usage` collection for cost tracking
- Handle timeouts (2 second max per API)
- Reference DESIGN-019 for API contracts

### Task 4: Implement Layer 2b Orchestration (Barcode-First Flow)

**Objective**: Create Firestore trigger that coordinates barcode → visual → parsing with fallbacks

**Acceptance Criteria (Given/When/Then)**:
- **Given** item status is `layer2a_complete` with optional `barcodeData`
- **When** Layer 2b trigger fires
- **Then** barcode lookup is attempted first (if barcode detected)
- **And** SerpAPI visual search is used if barcode lookup fails
- **And** Claude Haiku parsing runs on SerpAPI results
- **And** Firestore document is updated with `layer2b` field
- **And** status changes to `layer2b_complete` or `failed_layer2b`
- **And** cost savings are logged when barcode hits skip SerpAPI

**Test Example**:
```javascript
// Given: Item with barcode
const itemRef = db.collection('items').doc('test_barcode_item');
await itemRef.set({
  userId: 'test_user',
  imageUrl: 'https://storage.googleapis.com/.../coca_cola.jpg',
  barcodeData: { detected: true, value: '049000050103', type: 'EAN-13' },
  status: 'layer2a_complete'
});

// When: Trigger fires
await waitForTrigger(5000);

// Then
const item = await itemRef.get();
expect(item.data().status).toBe('layer2b_complete');
expect(item.data().layer2b.source).toBe('barcode');
expect(item.data().layer2b.barcodeAPI).toBe('openfoodfacts');
expect(item.data().layer2b.product.name).toContain('Coca-Cola');
```

- ⚠️ **Claude Haiku 4.5 Availability**: GA confirmed (no risk)
- ⚠️ **OpenFoodFacts API Stability**: Free tier, no SLA (LOW RISK)

### Risks Identified & Mitigations

#### Risk 1: UPCitemdb Pricing Not Verified ($99/month assumed)

**Likelihood**: Medium
**Impact**: High (cost model based on this assumption)

**Mitigation**:
- **Action**: Contact UPCitemdb sales to confirm $99/month DEV Plan pricing
- **Fallback**: Use Go-UPC ($0.0065/lookup) if UPCitemdb >$150/month
- **Trigger**: Verify pricing before production deployment

#### Risk 2: Claude Haiku 4.5 Pricing Increased + Cost Savings Overstated

**Likelihood**: Confirmed (already occurred)
**Impact**: Medium (Combined effect: Layer 2b cost increased, savings lower than claimed)

**Mitigation**:
- **Accepted**: Updated cost model with corrected probabilities
- **Corrected savings**: 22.6% API cost reduction, 6.1% monthly savings after fixed costs
- **Still profitable**: $36.37/month savings vs SerpAPI-only, 98.7% gross margin maintained
- **Optimization**: Use temperature=0.0 to minimize output tokens
- **Monitoring**: Track actual token usage vs estimates (500 input, 100 output)

#### Risk 3: SerpAPI Rate Limits (1,000 searches/hour)

**Likelihood**: Low (75K items/month = 104 items/hour avg)
**Impact**: Medium (items fail if burst exceeds 1,000/hour)

**Mitigation**:
- **Queue**: Implement request queue with rate limiting (max 900/hour)
- **Retry**: Exponential backoff for 429 errors
- **Monitoring**: Alert if queue depth >100 items

#### Risk 4: OpenFoodFacts API Unreliable (No SLA)

**Likelihood**: Medium (free API, community-driven)
**Impact**: Low (automatic fallback to UPCitemdb → SerpAPI)

**Mitigation**:
- **Timeout**: 2 second max, then fallback
- **Monitoring**: Track OpenFoodFacts success rate (target >90%)
- **Fallback**: UPCitemdb + SerpAPI ensure 99.9% product lookup success
