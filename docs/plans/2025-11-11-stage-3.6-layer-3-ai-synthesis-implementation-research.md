### Task 1: Claude Sonnet 4.5 Synthesis Function

**File**: `docs/design/CODE-EXAMPLE-016-claude-sonnet-synthesis.md`

**Objective**: Production-ready Node.js function for Layer 3 synthesis using Claude Sonnet 4.5 Batch API.

**Requirements**:
- Use correct model ID: `claude-sonnet-4-5-20250929`
- Merge Layer 2a attributes (category, color, material, condition, confidence)
- Merge Layer 2b product data (brand, model, variant, estimatedValue, source: barcode/serpapi)
- Use temperature 0.3 (consistent reasoning, not deterministic)
- Max tokens: 1024 (synthesis JSON ~200 tokens)

- Cost tracking: Log token usage to Firestore `ai_usage` collection

**Acceptance Criteria**:

```javascript
  And: Layer 2b result { source: "serpapi", product: { brand: "Coleman", name: "Triton", estimatedValue: 44.99 } }
When: synthesizeWithClaude(layer2a, layer2b, "backpack", "item_123")
Then: Return synthesized metadata with:
  - name: "Coleman Triton Camping Stove" (product name takes precedence)
  - brand: "Coleman" (from Layer 2b)
  - color: "green" (from Layer 2a, vision is authoritative for physical attributes)
  - condition: "good" (from Layer 2a)
  - estimatedValue: 31 (44.99 × 0.70 for "good" condition)
  - confidence: "high" (barcode match + consistent attributes)
  - conflictsResolved: [] (no conflicts)
  - reasoning: "Barcode match, consistent attributes, good condition"
  - model: "claude-sonnet-4-5"
  - tokensUsed: { input: 800, output: 200, total: 1000 }
```

**Code Structure**:
```javascript
// functions/src/services/claude-sonnet-synthesis.js

const Anthropic = require('@anthropic-ai/sdk');

async function synthesizeWithClaude(layer2a, layer2b, detectedLabel, itemId) {
    // 1. Initialize Anthropic client
    const anthropic = new Anthropic({ apiKey: process.env.ANTHROPIC_API_KEY });

    // 2. Build synthesis prompt (see Task 2)
    const prompt = buildSynthesisPrompt(layer2a, layer2b, detectedLabel);

    // 3. Call Claude Sonnet Batch API
    const message = await anthropic.messages.create({
        model: 'claude-sonnet-4-5-20250929', // CORRECTED
        max_tokens: 1024,
        temperature: 0.3, // Consistent reasoning
        messages: [{ role: 'user', content: prompt }]
    });

    // 4. Parse JSON response (regex fallback)
    const synthesized = extractJSON(message.content[0].text);

    // 5. Add metadata
    synthesized.model = 'claude-sonnet-4-5';
    synthesized.tokensUsed = {
        input: message.usage.input_tokens,
        output: message.usage.output_tokens,
        total: message.usage.input_tokens + message.usage.output_tokens
    };

    return synthesized;
}
```

**Test Cases** (Given/When/Then):
1. **Barcode match, no conflicts**: Synthesis succeeds, confidence "high"
2. **Color conflict (vision vs product)**: Vision color wins, conflict logged
3. **Category conflict (vision vs barcode)**: Barcode category wins
4. **Condition-adjusted pricing**: estimatedValue = baseValue × conditionMultiplier
5. **Missing product data**: Estimate value by category, confidence "low"
6. **Rate limit error (429)**: Retry with exponential backoff (60s, 120s, 240s)
7. **Malformed JSON**: Extract JSON via regex, handle edge cases

### Task 3: Confidence Scoring Algorithm

**File**: `docs/design/CODE-EXAMPLE-018-confidence-scoring.md`

**Objective**: Production-ready confidence calculation function with test cases.

**Algorithm**:
```javascript
function calculateConfidence(layer2a, layer2b, conflicts) {
    let score = 0;

    // Factor 1: Vision AI confidence (0-1) × 0.3 weight
    score += layer2a.confidence * 0.3;

    // Factor 2: Product Search source (barcode > visual search) × 0.4 weight
    if (layer2b.source === 'barcode') {
        score += 0.4; // Barcode authoritative
    } else if (layer2b.source === 'serpapi' && layer2b.serpapi.parsed.confidence > 0.7) {
        score += 0.3; // High-confidence visual search
    } else {
        score += 0.1; // Low-confidence visual search
    }

    // Factor 3: Conflict count (penalize conflicts) × 0.3 weight
    if (conflicts.length === 0) {
        score += 0.3; // No conflicts = high confidence
    } else if (conflicts.length <= 2) {
        score += 0.15; // Minor conflicts
    } else {
        score += 0.0; // Major conflicts
    }

    // Map score to confidence level
    if (score >= 0.8) return 'high';
    if (score >= 0.5) return 'medium';
    return 'low';
}
```

**Confidence Thresholds**:

| Confidence | Score | Meaning | User Action |
|------------|-------|---------|-------------|
| **High** | ≥ 0.8 | Barcode match + consistent attributes | No review needed |
| **Medium** | 0.5-0.8 | Visual search match with minor conflicts | Optional review |
| **Low** | < 0.5 | Major conflicts or no product match | User must review |

**Test Cases**:
```javascript
Given: layer2a.confidence = 0.87, layer2b.source = 'barcode', conflicts = []
When: calculateConfidence(layer2a, layer2b, conflicts)
Then: score = 0.261 + 0.4 + 0.3 = 0.961 → confidence = 'high'

Given: layer2a.confidence = 0.75, layer2b.source = 'serpapi', layer2b.serpapi.parsed.confidence = 0.85, conflicts = ['color']
When: calculateConfidence(layer2a, layer2b, conflicts)
Then: score = 0.225 + 0.3 + 0.15 = 0.675 → confidence = 'medium'

Given: layer2a.confidence = 0.60, layer2b.source = 'serpapi', layer2b.serpapi.parsed.confidence = 0.50, conflicts = ['color', 'category', 'brand']
When: calculateConfidence(layer2a, layer2b, conflicts)
Then: score = 0.18 + 0.1 + 0.0 = 0.28 → confidence = 'low'
```

**Acceptance Criteria**:
- Confidence calculation deterministic (same inputs = same output)
- Barcode match → always high or medium confidence (never low)
- 3+ conflicts → always low or medium confidence (never high)
- Test coverage: 5 scenarios covering all thresholds

### Task 4: Value Estimation Function

**File**: `docs/design/CODE-EXAMPLE-016-claude-sonnet-synthesis.md` (append)

**Objective**: Condition-adjusted pricing logic with category-based fallback.

**Algorithm**:
```javascript
function estimateValue(layer2b, condition) {
    let baseValue = 0;

    // Extract base value from product search
    if (layer2b.source === 'barcode' && layer2b.product.price) {
        baseValue = layer2b.product.price;
    } else if (layer2b.source === 'serpapi' && layer2b.product.estimatedValue) {
        baseValue = layer2b.product.estimatedValue;
    } else {
        // No price data, estimate by category
        baseValue = estimateByCategory(layer2b.product.category);
    }

    // Adjust for condition
    const conditionMultipliers = {
        'new': 1.0,
        'like-new': 0.85,
        'good': 0.70,
        'fair': 0.50,
        'poor': 0.30
    };

    return Math.round(baseValue * (conditionMultipliers[condition] || 0.70));
}

function estimateByCategory(category) {
    const categoryEstimates = {
        'camping': 50,
        'electronics': 100,
        'furniture': 150,
        'clothing': 30,
        'kitchenware': 25,
        'books': 10,
        'toys': 20,
        'sports': 75,
        'tools': 60,
        'other': 40
    };

    return categoryEstimates[category] || 40;
}
```

**Test Cases**:

```javascript
When: estimateValue({ product: { estimatedValue: 44.99 } }, "good")

When: estimateValue({ product: { estimatedValue: 100 } }, "poor")
Then: Return $30 (100 × 0.30 = 30)
```

### Task 5: Layer 3 Error Handling & Fallback

**File**: `docs/design/DESIGN-043-layer-3-error-handling.md`

**Objective**: Comprehensive error handling strategy for Layer 3 synthesis failures.

**Error Types**:

#### 1. Missing Layer 2 Data
**Cause**: Layer 2a or 2b incomplete
**Mitigation**: Log error, skip synthesis, mark item as `failed_layer3`
**Retry**: ❌ No (data dependency issue)

#### 2. Rate Limit (429)
**Cause**: Claude API rate limit exceeded
**Mitigation**: Exponential backoff, retry after 60s → 120s → 240s
**Retry**: ✅ Yes (3 attempts)

#### 3. Overloaded (529)
**Cause**: Claude API overloaded
**Mitigation**: Retry with exponential backoff
**Retry**: ✅ Yes (3 attempts)

#### 4. Malformed JSON
**Cause**: Claude response parsing error
**Mitigation**: Extract JSON via regex, log warning if edge case
**Retry**: ❌ No (use fallback extraction)

#### 5. Network Timeout
**Cause**: API timeout (>30s)
**Mitigation**: Retry once with extended timeout (60s)
**Retry**: ✅ Yes (1 attempt)

**Error Handling Code**:
```javascript
async function synthesizeWithErrorHandling(layer2a, layer2b, detectedLabel, itemId, retryCount = 0) {
    try {
        return await synthesizeWithClaude(layer2a, layer2b, detectedLabel, itemId);
    } catch (error) {
        if (error.status === 429 && retryCount < 3) {
            // Rate limit: Exponential backoff
            const delay = Math.pow(2, retryCount) * 60000; // 60s, 120s, 240s
            await sleep(delay);
            return synthesizeWithErrorHandling(layer2a, layer2b, detectedLabel, itemId, retryCount + 1);
        } else if (error.type === 'overloaded_error' && retryCount < 3) {
            // Overloaded: Exponential backoff
            const delay = Math.pow(2, retryCount) * 30000; // 30s, 60s, 120s
            await sleep(delay);
            return synthesizeWithErrorHandling(layer2a, layer2b, detectedLabel, itemId, retryCount + 1);
        } else {
            // Unrecoverable error
            throw new SynthesisError(`Layer 3 failed after ${retryCount} retries`, error);
        }
    }
}
```

**Fallback Strategy**:
```
IF Layer 3 synthesis fails (after 3 retries):
  → Use Layer 2a + 2b data without synthesis
  → Set confidence = "low"
  → Mark item as "requires_review"
  → Log to dead letter queue for manual processing
```

**Acceptance Criteria**:
- All 5 error types handled with appropriate retry logic
- Exponential backoff tested (verify delay timing)
- Dead letter queue integration tested
- Firestore item marked with error state (`failed_layer3`, error message, timestamp)

## Risks & Mitigations

### Risk 1: JSON Parsing Failures (14-20% edge cases)

- **Impact**: Medium (synthesis data incomplete)
- **Probability**: Medium (Claude lacks native JSON mode)
- **Mitigation**: Regex extraction fallback, log edge cases, retry with stricter prompt

### Risk 2: Batch Processing Delays (up to 24h)

- **Impact**: Low (async cataloging UX absorbs delay)
- **Probability**: Medium (batch API has variable processing time)
- **Mitigation**: Progressive disclosure UX (Layer 1/2a/2b → Layer 3 fills in later), set user expectations

### Risk 3: Cost Calculation Drift

- **Impact**: Medium (margin erosion if token usage exceeds estimates)
- **Probability**: Medium (synthesis prompts may expand over time)
- **Mitigation**: Monitor actual token usage, adjust max_tokens, use temperature 0.3 for consistency

### Risk 4: Conflict Resolution Accuracy <90%

- **Impact**: Medium (user correction rate increases)
- **Probability**: Medium (90% claim unverified from official sources)
