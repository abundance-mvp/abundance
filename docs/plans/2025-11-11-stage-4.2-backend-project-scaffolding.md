### Task 1: Create Firestore Security Rules (firestore.rules)

**Objective**: Translate SECURITY-RULES-001 specification into runnable Firestore security rules file.

**Input**: docs/design/SECURITY-RULES-001-firestore-rules.md

**Output**: docs/tech-stack/firestore.rules

**Implementation Details**:

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Helper functions
    function isSignedIn() {
      return request.auth != null;
    }

    function isOwner(userId) {
      return isSignedIn() && request.auth.uid == userId;
    }

    function isPremium() {
      return isSignedIn() && request.auth.token.premium == true;
    }

    // Users collection: users can only read/write their own profile
    match /users/{userId} {
      allow read: if isOwner(userId);
      allow create: if isOwner(userId) && request.resource.data.userId == userId;
      allow update: if isOwner(userId) && request.resource.data.userId == userId;
      allow delete: if false; // Users cannot delete their own accounts
    }

    // Items collection: users can only access their own items
    match /items/{itemId} {
      allow read: if isSignedIn() && resource.data.userId == request.auth.uid;

      allow create: if isSignedIn()
        && request.resource.data.userId == request.auth.uid
        && request.resource.data.status == 'processing'
        && request.resource.data.deletedAt == null;

      allow update: if isSignedIn()
        && resource.data.userId == request.auth.uid
        && request.resource.data.userId == resource.data.userId; // Can't change ownership

      allow delete: if false; // Soft delete only (via update)
    }

    // Subscriptions collection: read-only for users, write-only for Cloud Functions
    match /subscriptions/{subscriptionId} {
      allow read: if isSignedIn() && resource.data.userId == request.auth.uid;
      allow write: if false; // Only Cloud Functions can write via Admin SDK
    }
  }
}
```

- Helper functions match SECURITY-RULES-001 patterns
- Row-level security enforced via `userId` field checks

### Task 2: Create Firebase Storage Security Rules (storage.rules)

**Objective**: Translate STORAGE-RULES-001 specification into runnable Firebase Storage security rules file.

**Input**: docs/design/STORAGE-RULES-001-firebase-storage-rules.md

**Output**: docs/tech-stack/storage.rules

**Implementation Details**:

```javascript
rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {

    // Helper functions
    function isSignedIn() {
      return request.auth != null;
    }

    function isOwner(userId) {
      return isSignedIn() && request.auth.uid == userId;
    }

    // User-uploaded images: users/{userId}/items/{itemId}/*.jpg
    match /users/{userId}/items/{itemId}/{fileName} {
      allow read: if isOwner(userId);

      allow write: if isOwner(userId)
        && request.resource.size < 10 * 1024 * 1024 // 10MB limit
        && request.resource.contentType.matches('image/.*'); // Images only

      allow delete: if isOwner(userId);
    }

    // Processed images (AI pipeline): processed/{itemId}/*.jpg
    // Only accessible via signed URLs (generated by Cloud Functions)
    match /processed/{itemId}/{fileName} {
      allow read: if false; // No direct access
      allow write: if false; // Only Cloud Functions can write via Admin SDK
    }
  }
}
```

**Verification**:
- Syntax validated against RESEARCH-VALIDATION-stage-4.2.md (Claim 3)
- File size limits enforced (10MB per upload)

## Risks & Mitigations

### Risk 1: Firestore Rules Compilation Errors

- **Impact**: Medium (deployment blocked until fixed)
- **Probability**: Low (syntax verified against RESEARCH-VALIDATION-stage-4.2.md)
- **Mitigation**: Test rules locally with Firebase Emulator Suite before deployment

### Risk 2: Cloud Functions Build Errors

- **Impact**: Medium (deployment blocked)
- **Probability**: Low (TypeScript scaffold uses verified patterns)
- **Mitigation**: Run `npm run build` locally before deployment, add predeploy hook

### Risk 3: Missing API Keys in Secret Manager

- **Impact**: High (Cloud Functions fail at runtime)
- **Probability**: Medium (manual secret setup required)
- **Mitigation**: Document secret setup in README-Backend-Setup.md, create setup checklist

### Risk 4: Firestore Index Deployment Lag

- **Impact**: Low (queries temporarily fail until indexes build)
- **Probability**: High (Firestore indexes can take minutes to build)
- **Mitigation**: Deploy indexes first (`firebase deploy --only firestore:indexes`), wait for confirmation before deploying functions
