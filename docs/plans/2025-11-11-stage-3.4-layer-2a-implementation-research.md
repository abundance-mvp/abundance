## Background & Context

Stage 3.4 creates **production-ready implementation patterns** for Layer 2a of the AI cataloging pipeline - attribute extraction using Vertex AI Gemini 2.5 Flash-Lite. This stage bridges the gap between strategic technology decisions (Stage 2.0) and actual code that AI agents will execute.

**What Layer 2a Does**:
- Receives cropped object images from iOS (uploaded to GCS)
- Calls Vertex AI Gemini 2.5 Flash-Lite with JSON Schema Mode
- Extracts visual attributes: category, color, material, condition
- Writes structured results to Firestore
- Triggers Layer 2b (product search)

**Why This Stage Matters**:
- DESIGN-017 exists but needs verification against current (2025) Vertex AI SDK
- Stage 3.2 provided Cloud Functions patterns, now apply to Layer 2a specifically
- Stage 2.0 verified Gemini exists, now we need implementation-level code examples
- AI agents need working code, not conceptual architecture

### Error Codes & Retry Strategy

**Verified Error Codes**:
- `429` (RESOURCE_EXHAUSTED): Rate limit exceeded
- `QUOTA_EXCEEDED`: Daily/monthly quota reached
- `DEADLINE_EXCEEDED`: Request timeout (30s default)
- `UNAVAILABLE`: Transient network error

**Verified Retry Pattern**:
```javascript
async function retryWithExponentialBackoff(fn, maxRetries = 5) {
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    try {
      return await fn();
    } catch (error) {
      if (!error.retryable || attempt === maxRetries - 1) throw error;

      const delay = Math.min(Math.pow(2, attempt) * 1000, 60000); // Cap at 60s
      await new Promise(resolve => setTimeout(resolve, delay));
    }
  }
}
```

**Critical Note**: Google's research shows 80% of failures without backoff vs 100% success with exponential backoff. **Retry logic is mandatory for production**.

### Task 3: JSON Schema Design Document

**Document**: `docs/design/DESIGN-041-layer-2a-json-schema.md`

**Requirements**:
- Complete OpenAPI 3.0 schema for attribute extraction
- Enum constraints for category (10 values) and condition (5 values)
- String fields with descriptions for color/material
- Confidence field (number, 0.0-1.0)
- Required vs optional fields
- Validation error handling

**Schema Structure** (verified OpenAPI 3.0 format):
```json
{
  "type": "object",
  "properties": {
    "category": {
      "type": "string",
      "description": "Primary household item category",
      "enum": ["camping", "electronics", "furniture", "clothing", "kitchenware", "books", "toys", "sports", "tools", "other"]
    },
    "color": {
      "type": "string",
      "description": "Primary visible color"
    },
    "material": {
      "type": "string",
      "description": "Primary material (metal, plastic, fabric, wood, glass, other)"
    },
    "condition": {
      "type": "string",
      "description": "Visual condition assessment",
      "enum": ["new", "like-new", "good", "fair", "poor"]
    },
    "confidence": {
      "type": "number",
      "description": "Overall confidence in extraction (0.0-1.0)",
      "minimum": 0,
      "maximum": 1
    }
  },
  "required": ["category", "color", "condition"]
}
```

**Design Rationale**:
- Category enum prevents hallucinations (only 10 valid values)
- Condition enum ensures consistent condition scale
- Color/material as strings allow flexibility (many variations)
- Confidence field enables downstream filtering

**Requirements**:

- Retry strategy per error type (retryable vs non-retryable)
- Exponential backoff implementation (verified pattern)
- Dead letter queue design (failed items after 3 retries)
- Monitoring alerts (error rate > 5%, quota at 80%)

**Error Handling Table**:
| Error Code | Meaning | Retryable? | Strategy | Max Retries |
|------------|---------|------------|----------|-------------|
| 429 (RESOURCE_EXHAUSTED) | Rate limit exceeded | ✅ Yes | Exponential backoff (1s, 2s, 4s, 8s, 16s) | 5 |
| QUOTA_EXCEEDED | Daily/monthly quota reached | ❌ No | Log alert, notify team, wait for reset | 0 |
| DEADLINE_EXCEEDED | Request timeout (30s) | ✅ Yes | Retry with same timeout | 3 |
| UNAVAILABLE | Transient network error | ✅ Yes | Exponential backoff | 5 |
| INVALID_ARGUMENT | Malformed request | ❌ No | Log error, skip item | 0 |
| NOT_FOUND | Image URL invalid | ❌ No | Log error, skip item | 0 |

**Dead Letter Queue Pattern**:
```javascript
// After max retries exhausted:
await firestore.collection('failedItems').doc(itemId).set({
  itemId,
  userId,
  layer: 'layer2a',
  errorMessage: error.message,
  errorCode: error.code,
  failedAt: Timestamp.now(),
```

## Risks & Mitigations

### Risk 1: Gemini API Changes Since Research Validation
- **Impact**: Medium (code examples may not compile)
- **Probability**: Low (verification done 2025-11-11, implementation immediate)
- **Mitigation**: Reference official Google Cloud docs during execution, update code if API changed

### Risk 2: Accuracy Below Acceptance Criteria (< 85% category)
- **Impact**: High (may need to switch to GPT-4V, 30× cost increase)
- **Probability**: Medium (YOLOv3-Tiny provides coarse category, Gemini refines)
- **Mitigation**: Benchmark early (Task 6), use few-shot prompts if needed, fallback to Layer 3 Claude synthesis

### Risk 3: Rate Limiting During Benchmarking
- **Impact**: Low (delays testing, doesn't block implementation)
- **Probability**: Medium (50-100 API calls in short time)
- **Mitigation**: Use exponential backoff (verified pattern), spread benchmark over 24 hours if needed

### Risk 4: JSON Schema Validation Failures
- **Impact**: Medium (parsing errors, no structured output)
- **Probability**: Low (JSON Schema Mode designed to prevent this)
- **Mitigation**: Include fallback parsing logic, log schema violations, retry with adjusted prompt

### Risk 5: Cost Exceeds Budget ($0.0001 per image target)
- **Impact**: Low (still within margins even at $0.0005)
- **Probability**: Low (verified cost ~$0.00004 per image)
- **Mitigation**: Monitor actual token usage, optimize prompt length if needed, cache common attributes
