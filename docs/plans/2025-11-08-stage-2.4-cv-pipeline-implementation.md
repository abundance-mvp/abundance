## Implementation Tasks

### Task Group 1: Layer 1 iOS Implementation Design

**Objective**: Specify on-device computer vision implementation for iOS

**Subtasks**:

1. **AVFoundation Camera Integration** (DESIGN-012: Camera Capture Implementation)
   - AVCaptureSession configuration
   - Photo capture workflow
   - Temporary storage patterns
   - Memory management

   **Acceptance Criteria**:
   - Given: User taps "Capture Item"
   - When: Camera session initializes
   - Then: Photo captured to temporary storage within 500ms

   **Code Example**:
   ```swift
   // AVCaptureSession setup pattern
   class CameraService {
       private let captureSession = AVCaptureSession()

       func configureCaptureSession() throws {
           captureSession.beginConfiguration()
           captureSession.sessionPreset = .photo

           guard let camera = AVCaptureDevice.default(.builtInWideAngleCamera,
                                                       for: .video,
                                                       position: .back) else {
               throw CameraError.deviceNotAvailable
           }

           let input = try AVCaptureDeviceInput(device: camera)
           guard captureSession.canAddInput(input) else {
               throw CameraError.cannotAddInput
           }
           captureSession.addInput(input)

           let photoOutput = AVCapturePhotoOutput()
           guard captureSession.canAddOutput(photoOutput) else {
               throw CameraError.cannotAddOutput
           }
           captureSession.addOutput(photoOutput)

           captureSession.commitConfiguration()
       }
   }
   ```

2. **Vision Framework Object Detection** (DESIGN-013: Vision Framework Integration Patterns)
   - VNCoreMLRequest initialization with YOLOv3-Tiny
   - VNImageRequestHandler usage
   - Bounding box coordinate transformation
   - Object cropping from CGImage
   - Neural Engine optimization flags

   **Acceptance Criteria**:
   - Given: Photo captured from camera
   - When: Vision Framework analyzes image
   - Then: Objects detected with bounding boxes (80 COCO classes, >60% confidence)

   **Code Example**:
   ```swift
   // VNCoreMLRequest with YOLOv3-Tiny
   func detectObjects(in image: UIImage) async throws -> [DetectedObject] {
       guard let cgImage = image.cgImage else {
           throw VisionError.invalidImage
       }

       let model = try VNCoreMLModel(for: YOLOv3Tiny().model)
       let request = VNCoreMLRequest(model: model)
       request.imageCropAndScaleOption = .scaleFill

       let handler = VNImageRequestHandler(cgImage: cgImage, options: [:])
       try handler.perform([request])

       guard let results = request.results as? [VNRecognizedObjectObservation] else {
           return []
       }

       return results
           .filter { $0.confidence > 0.6 }
           .map { observation in
               DetectedObject(
                   label: observation.labels.first?.identifier ?? "unknown",
                   confidence: observation.confidence,
                   boundingBox: observation.boundingBox,
                   croppedImage: cropImage(cgImage, to: observation.boundingBox)
               )
           }
   }
   ```

3. **Barcode Scanning** (DESIGN-014: Barcode Detection Implementation)
   - VNDetectBarcodesRequest usage
   - Symbology filtering (UPC-A, EAN-13, QR Code)
   - Barcode value extraction
   - Parallel detection (objects + barcodes)

   **Acceptance Criteria**:
   - Given: Photo contains product with barcode
   - When: Vision Framework scans
   - Then: Barcode value extracted (24 symbologies supported)

   **Code Example**:
   ```swift
   // VNDetectBarcodesRequest
   func detectBarcodes(in image: UIImage) async throws -> [String] {
       guard let cgImage = image.cgImage else {
           throw VisionError.invalidImage
       }

       let request = VNDetectBarcodesRequest()
       request.symbologies = [.upce, .ean8, .ean13, .qr, .code128]

       let handler = VNImageRequestHandler(cgImage: cgImage, options: [:])
       try handler.perform([request])

       guard let results = request.results as? [VNBarcodeObservation] else {
           return []
       }

       return results.compactMap { $0.payloadStringValue }
   }
   ```

4. **Privacy Firewall Enforcement** (DESIGN-015: Privacy Architecture)
   - Full photo never uploaded
   - Only cropped objects leave device
   - Temporary photo deletion
   - User consent patterns

   **Acceptance Criteria**:
   - Given: Objects detected
   - When: Upload to cloud
   - Then: Only cropped object images sent, full photo deleted from temp storage

### Task Group 2: Layer 2a Cloud AI Integration

**Objective**: Specify Gemini Vision attribute extraction implementation

**Subtasks**:

1. **GCS Upload from iOS** (DESIGN-016: Cloud Storage Upload Patterns)
   - Firebase Storage SDK usage
   - Cropped image upload
   - Progress tracking
   - Signed URL retrieval

   **Code Example**:
   ```swift
   // Firebase Storage upload
   func uploadCroppedObject(_ image: UIImage, itemId: String) async throws -> URL {
       guard let imageData = image.jpegData(compressionQuality: 0.8) else {
           throw StorageError.invalidImage
       }

       let storage = Storage.storage()
       let ref = storage.reference()
           .child("users/\(currentUserId)/items/\(itemId)/cropped.jpg")

       let metadata = StorageMetadata()
       metadata.contentType = "image/jpeg"

       _ = try await ref.putDataAsync(imageData, metadata: metadata)

       let downloadURL = try await ref.downloadURL()
       return downloadURL
   }
   ```

2. **Gemini Vision API Integration** (DESIGN-017: Vertex AI Integration Patterns)
   - Cloud Functions → Vertex AI client
   - JSON schema mode configuration
   - Structured output parsing
   - Error handling (rate limits, timeouts)

   **Code Example (Node.js)**:
   ```javascript
   // Cloud Function: Layer 2a Attribute Extraction
   const { VertexAI } = require('@google-cloud/vertexai');

   async function extractAttributes(imageUrl) {
       const vertexAI = new VertexAI({
           project: 'abundance-prod',
           location: 'us-central1'
       });

       const model = vertexAI.preview.getGenerativeModel({
           model: 'gemini-2.0-flash-exp',
           generationConfig: {
               responseSchema: {
                   type: 'object',
                   properties: {
                       category: { type: 'string' },
                       color: { type: 'string' },
                       material: { type: 'string' },
                       condition: { type: 'string', enum: ['new', 'like-new', 'good', 'fair', 'poor'] }
                   },
                   required: ['category', 'color']
               },
               responseMimeType: 'application/json'
           }
       });

       const result = await model.generateContent({
           contents: [{
               role: 'user',
               parts: [
                   { text: 'Analyze this household item and extract attributes.' },
                   { fileData: { fileUri: imageUrl, mimeType: 'image/jpeg' } }
               ]
           }]
       });

       return JSON.parse(result.response.text());
   }
   ```

### Task Group 5: Cross-Layer Integration & Orchestration

**Objective**: Specify end-to-end flow and error handling

**Subtasks**:

1. **Firestore Trigger Orchestration** (DESIGN-021: Cloud Functions Orchestration)
   - onItemCreated → Layer 2a
   - onLayer2aComplete → Layer 2b
   - onLayer2bComplete → Layer 3
   - onLayer3Complete → Update item status

   **Sequence Diagram**:
   ```
   iOS                   Cloud Functions          Firestore           AI APIs
    |                         |                       |                  |
    |--Photo + metadata------>|                       |                  |
    |                         |---Create item-------->|                  |
    |                         |                       |                  |
    |                         |<--onItemCreated-------|                  |
    |                         |---Layer 2a----------->|--Gemini--------->|
    |                         |<--Attributes----------|<-----------------|
    |                         |---Update item-------->|                  |
    |                         |                       |                  |
    |                         |<--onLayer2aComplete---|                  |
    |                         |---Layer 2b----------->|--SerpAPI-------->|
    |                         |<--Product data--------|<--Claude Haiku---|
    |                         |---Update item-------->|                  |
    |                         |                       |                  |
    |                         |<--onLayer2bComplete---|                  |
    |                         |---Layer 3------------>|--Claude Sonnet-->|
    |                         |<--Synthesis-----------|<-----------------|
    |                         |---Final update------->|                  |
    |<--Real-time listener----|<---------------------|                  |
   ```

2. **Error Handling per Layer** (DESIGN-022: Error Handling Architecture)
   - Layer 1: Vision failures → show user error, retry
   - Layer 2a: Gemini timeout → mark item as "partial", manual retry
   - Layer 2b: SerpAPI failure → use Layer 2a only
   - Layer 3: Claude failure → save Layer 2 results, flag for review

   **Error State Machine**:
   ```
   Item States:
   - "pending" (just created, awaiting Layer 2a)
   - "layer2a_complete" (attributes extracted)
   - "layer2b_complete" (product search done)
   - "complete" (synthesis done)
   - "failed_layer2a" (Gemini failed)
   - "failed_layer2b" (SerpAPI failed, using Layer 2a only)
   - "failed_layer3" (Claude failed, manual review needed)
   ```

3. **Retry Logic** (DESIGN-023: Retry Strategy)
   - Exponential backoff for API failures
   - Maximum retry attempts (3 per layer)
   - Dead letter queue for persistent failures

4. **Real-time UI Updates** (DESIGN-024: Firestore Listener Patterns)
   - iOS Firestore listener on items collection
   - Real-time status updates in UI
   - Progress indicator (Layer 1 → 2a → 2b → 3)
